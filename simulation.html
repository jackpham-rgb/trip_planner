Why a bandit, not just "pick the top score"?

This runs the same comparison scripts/simulate_bandit.py used to print to a terminal (see docs/history/) -- Thompson sampling vs. epsilon-greedy vs. picking randomly -- but live, in the browser, using the exact ThompsonBandit class from recommender.js that the real app runs. A made-up "true" preference vector stands in for taste that's never directly observable; each strategy only sees noisy rewards and has to learn from them.
